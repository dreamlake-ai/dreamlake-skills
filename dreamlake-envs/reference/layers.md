# Env layers — authoring `dreamlake.layers.json`

Source: the owning docs are the [Env Layers Reference](https://docs.dreamlake.ai/envs/layers)
and the [Envs guide § Env layers](https://docs.dreamlake.ai/envs#env-layers).
This file is reconciled explicitly with those pages (schema
`dreamlake.env-layers/v2`, RFC 0007 — frozen); it is not generated by the
Notes/CLI synchronizer. On any conflict, the live docs win.

## Model, compressed

A layered env is an ordered **stack** of layers; every layer is itself an
env (or a local dir / patch file) with its own **compose rule**. No layer
has a privileged role — "scene", "embodiment", "physics profile" are usage,
not schema. Applied in order, **later wins, always**. `dreamlake env
compose` materializes the stack (a real MuJoCo build) into an ordinary
`mujoco` env directory — entry + flat assets + a fully **pinned** copy of
the stack — and `dreamlake env push` publishes it as a normal env version.
Consumers only ever read the materialized artifact; the embedded stack
keeps the env re-openable (edit a pin/pose/opinion → recompose → push;
dedup keeps re-pushes cheap).

## From the user's words to a stack

| user says | stack construct |
| --- | --- |
| "combine X and Y", "X plus my physics/lighting profile" | `merge` layers, in order (later wins field-wise for `option`/`visual`/`compiler`) |
| "put / place / mount ROBOT in SCENE" | scene as `merge`, robot as `attach` (`prefix`, `at`, `pos`, `joint`) |
| "three mugs", "scatter N copies of X" | one `attach` entry with `instances` (per-instance `prefix`/`pos`/`quat`) |
| "move / recolor / dim / retune …" | `override` layer — sparse MJCF carrying only the changed attributes |
| "remove / delete the plant" | `delete` on an `override` rule (not layer content) |
| "start from my composed env and add …" | nested stack: `merge` the pushed composed env as the base layer, stack more above |
| "use my local folder while I iterate" | `{"path": "./dir"}` source — compose freely; push is gated (below) |

Choosing `joint` for an attach: bolted-down arm / sensor rig / fixture →
`"rigid"`; free-standing prop under gravity → `"free"`; hand or gripper
hanging posed and draggable → `"free-anchored"` (freejoint + mocap-anchor
weld).

## Field reference (distilled)

Top level:

| field | required | meaning |
| --- | --- | --- |
| `schema` | yes | `"dreamlake.env-layers/v2"`, verbatim |
| `substrate` | no (default `"mujoco"`) | the only substrate today; non-mujoco layers admitted only via an importer (`urdf`, attach-only) |
| `entry` | yes | output entry filename, e.g. `"scene.xml"` |
| `name` | no | MJCF model name of the output |
| `layers` | yes | ordered entries, applied first → last |

`layers[].source` — exactly one of:

- `{"env": "ns/name"}` or `{"env": "ns/name@3"}` — pushed env; unversioned
  floats (resolved at compose; the artifact-embedded stack is always pinned `@v`).
- `{"path": "./dir"}` — local directory in standard env shape; dev-only for push.
- `{"file": "patches/x.xml"}` — a file inside the stack's own directory; for
  a small sparse-MJCF override patch that doesn't warrant its own env.

`layers[].compose` by mode:

- `{"mode": "merge"}` — no further fields. Section-wise union; a name
  collision between merged layers is an **error** (changing things is
  override's job). Exception: `option`/`visual`/`compiler` settings merge
  field-wise, later layer wins per field.
- `{"mode": "attach", …}`:

  | field | required | meaning |
  | --- | --- | --- |
  | `prefix` | yes, unless `instances` | prepended to every name and name-reference in the layer (`right:` → `right:palm`) |
  | `at` | yes | `"world"`, `"body:<name>"`, or `"site:<name>"` (site pose wins; target may come from any lower layer) |
  | `pos` | no, default `[0,0,0]` | mount position |
  | `quat` | no, default `[1,0,0,0]` | mount orientation (MuJoCo `[w,x,y,z]`) |
  | `joint` | yes | `"rigid"` / `"free"` / `"free-anchored"` |
  | `instances` | no | `[{"prefix": "a:", "pos": […], "quat": […]}, …]` — replaces top-level `prefix`/`pos`/`quat`; `at`/`joint` shared; each instance is its own identity root |

- `{"mode": "override", "delete": […]}` — layer content is **sparse MJCF**:
  elements matched to the stack below by (kind, name), the attributes
  present are the opinions, nothing else is touched. Matching is **strict**
  (unknown name = compose error with layer index, not a no-op). `delete` is
  optional rule metadata: `[{"elem": "body", "name": "fixture/plant"}]`
  removes the element and its subtree from the stack below — reversible by
  dropping the layer.

Other frozen semantics: stacks containing any attach layer strip
`<keyframe>` entries (attach changes dof count); nested composed envs enter
as one layer via their materialized artifact (never unpacked; cycles
rejected); the pinned stack copy records
`"builder": {"engine": "dreamlake-py/<v>", "mujoco": "<v>"}`; local-path
sources embed as `{"path": …, "unpinned": true}`.

## Workflow

```bash
pip install "dreamlake[compose]"   # once, on the composing machine (python + mujoco)

dreamlake env compose              # materialize ./dreamlake.layers.json (or: compose <path>)
dreamlake env push <out-dir>       # artifact + pinned stack as one version
```

The CLI delegates materialization to the dreamlake-py engine; push / pull /
list need no Python. Registry layers resolve through the immutable cache
`~/.dreamlake/cache/envs/<ns>/<name>/<version>/`.

**Push discipline** — pushing a directory whose stack contains local
`{"path": …}` sources is refused:

- `--push-layers` — push those layers as their own envs first, then the
  composed env. Prefer this: provenance stays resolvable.
- `--allow-local` — push anyway; provenance permanently marked
  non-resolvable. Use only when the user explicitly accepts that.

## The six stack shapes

1. **Scene + embodiment** (swap = edit one line, recompose, push):

```json
{ "schema": "dreamlake.env-layers/v2", "entry": "scene.xml", "name": "kitchen-sharpa",
  "layers": [
    { "source": { "env": "you/kitchen@3" }, "compose": { "mode": "merge" } },
    { "source": { "env": "you/sharpa-right@1" },
      "compose": { "mode": "attach", "prefix": "right:", "at": "world",
                   "pos": [0.45, -0.12, 0.30], "quat": [1, 0, 0, 0],
                   "joint": "free-anchored" } } ] }
```

2. **Override patch + delete** (patch file lives inside the stack's dir):

```json
{ "schema": "dreamlake.env-layers/v2", "entry": "scene.xml",
  "layers": [
    { "source": { "env": "you/kitchen@3" }, "compose": { "mode": "merge" } },
    { "source": { "file": "patches/night.xml" },
      "compose": { "mode": "override",
                   "delete": [ { "elem": "body", "name": "fixture/plant" } ] } } ] }
```

```xml
<!-- patches/night.xml — sparse MJCF: only the stated attributes change -->
<mujoco model="night">
  <worldbody>
    <body name="obj/mug" pos="0.30 0.10 0.02"/>
    <light name="key" diffuse="0.3 0.3 0.4"/>
  </worldbody>
  <option impratio="10"/>
</mujoco>
```

3. **Multi-instance attach** (an override above can target `mug2:*` alone):

```json
{ "schema": "dreamlake.env-layers/v2", "entry": "scene.xml",
  "layers": [
    { "source": { "env": "you/kitchen@3" }, "compose": { "mode": "merge" } },
    { "source": { "env": "you/mug@2" },
      "compose": { "mode": "attach", "at": "world", "joint": "free",
                   "instances": [
                     { "prefix": "mug1:", "pos": [0.30, 0.10, 0.05] },
                     { "prefix": "mug2:", "pos": [0.42, -0.08, 0.05] } ] } } ] }
```

4. **URDF robot layer** (attach-only; see caveats):

```json
{ "schema": "dreamlake.env-layers/v2", "entry": "scene.xml", "name": "berry-g1",
  "layers": [
    { "source": { "env": "you/scene-berry@1" }, "compose": { "mode": "merge" } },
    { "source": { "env": "you/g1@1" },
      "compose": { "mode": "attach", "prefix": "g1:", "at": "world",
                   "pos": [0, 0, 0.8], "joint": "free" } } ] }
```

5. **Nested stack** (a pushed composed env is one layer; site targets can
   come from inside it, prefixes included):

```json
{ "schema": "dreamlake.env-layers/v2", "entry": "scene.xml",
  "layers": [
    { "source": { "env": "you/kitchen-sharpa@2" }, "compose": { "mode": "merge" } },
    { "source": { "env": "you/wrist-cam-rig@1" },
      "compose": { "mode": "attach", "prefix": "cam:",
                   "at": "site:right:palm-mount", "joint": "rigid" } },
    { "source": { "env": "you/kitchen-nightshift@1" },
      "compose": { "mode": "override" } } ] }
```

6. **Local-dir dev flow** (compose freely; push is gated):

```json
{ "schema": "dreamlake.env-layers/v2", "entry": "scene.xml",
  "layers": [
    { "source": { "path": "./kitchen" }, "compose": { "mode": "merge" } },
    { "source": { "env": "you/sharpa-right@1" },
      "compose": { "mode": "attach", "prefix": "right:", "at": "world",
                   "pos": [0.45, -0.12, 0.30], "joint": "free-anchored" } } ] }
```

## Errors and remedies

| error | when | remedy |
| --- | --- | --- |
| merge name collision | two merge layers define a same-named element | rename in one layer; if the upper layer is meant to *change* it, make that layer an `override` |
| override strict-match miss | an opinion or `delete` names an element the stack below doesn't have (error reports the layer index) | fix the typo; after an `attach`, target the **prefixed** name (`right:palm`, `mug2:handle`) |
| env source not resolved ("resolve refs first") | the Python engine was invoked directly on a stack still containing `{"env": …}` sources | run through `dreamlake env compose` (it resolves refs into the cache first); for private layers check the active login/remote |
| missing Python engine | dreamlake-py or its mujoco extra is absent on the composing machine | `pip install "dreamlake[compose]"`; machines that only push/pull/list don't need it |

## Caveats (verified, not hypothetical)

- **URDF layers are attach-only** (URDF cannot express a world) and import
  **unactuated**: URDF `<transmission>` has no MuJoCo mapping, so the robot
  arrives with `nu = 0` and goes limp under gravity in a physics stack. The
  compose report carries an "unactuated import" warning. Remedy inside the
  stack model: add an override layer contributing damping/actuators, or
  present the layer as visualization-grade in the env description. The
  composer also reconciles a root freejoint the URDF may already declare —
  it never double-adds one.
- **Prefix targeting**: `attach` manufactures new identities by prefixing;
  every override (and `delete`) above must use the prefixed names.
- **Strict matching is a feature**: an override naming a missing element
  fails compose deliberately — never "fix" it by removing the opinion
  without checking whether the stack order or a prefix is what's wrong.
- **Order is the priority.** Base content first, attaches next, opinions
  last is the conventional reading order; whatever you write, later wins.
- **Pin when it matters**: floating refs (`you/kitchen`) re-resolve on every
  compose; pin `@v` for reproducibility. The artifact's embedded stack is
  always pinned regardless.
