# Env layers — authoring `dreamlake.layers.json`

Source: the owning docs are the [Env Layers Reference](https://docs.dreamlake.ai/envs/layers)
and the [Envs guide § Env layers](https://docs.dreamlake.ai/envs#env-layers).
This file is reconciled explicitly with those pages (schema
`dreamlake.env-layers/v3`, RFC 0007 — the vuer-style component grammar);
it is not generated by the Notes/CLI synchronizer. On any conflict, the
live docs win.

## Model, compressed

A layered env is an ordered **stack** of flat ops — every entry is one
object `{"tag": ..., ...props}`, in the vocabulary of vuer's imperative
session updates, with `Update` as a *meta component* (its `key` addresses
an element, its props ARE the opinions). No op has a privileged role —
"scene", "embodiment", "physics profile" are usage, not schema. Applied
in order, **later wins, always**. `dreamlake env compose` materializes
the stack (a real MuJoCo build) into an ordinary `mujoco` env directory —
entry + flat assets + a fully **pinned** copy of the stack — and
`dreamlake env push` publishes it as a normal env version. Consumers only
ever read the materialized artifact; the embedded stack keeps the env
re-openable (edit a pin/pose/opinion → recompose → push; dedup keeps
re-pushes cheap).

## From the user's words to a stack

| user says | stack construct |
| --- | --- |
| "combine X and Y", "X plus my physics/lighting profile" | `Merge` ops, in order (later wins field-wise for `option`/`visual`/`compiler`) |
| "put / place / mount ROBOT in SCENE" | scene as `Merge`, robot as `Attach` (`key`, `at`, `pos`, `joint`) |
| "three mugs", "scatter N copies of X" | N `Attach` entries, one per placement (`mug1`, `mug2`, …) |
| "move / recolor / dim / retune one thing" | an inline `Update` — `{"tag": "Update", "key": "obj/mug", "pos": […]}` |
| "a whole lighting/tuning pass" | a `Patch` op — sparse MJCF file or a pushed opinion env |
| "remove / delete the plant" | `{"tag": "Remove", "key": "body:fixture/plant"}` |
| "start from my composed env and add …" | nested stack: `Merge` the pushed composed env as the base, stack more above |
| "use my local folder while I iterate" | `"src": "./dir"` — compose freely; push is gated (below) |

Choosing `joint` for an Attach: bolted-down arm / sensor rig / fixture →
`"rigid"`; free-standing prop under gravity → `"free"`; hand or gripper
hanging posed and draggable → `"free-anchored"` (freejoint + mocap-anchor
weld).

## Field reference (distilled)

Top level (`schema` + `layers` is a complete stack):

| field | required | meaning |
| --- | --- | --- |
| `schema` | yes | `"dreamlake.env-layers/v3"`, verbatim |
| `layers` | yes | ordered ops, applied first → last |
| `substrate` | no (default `"mujoco"`) | the only substrate today; non-mujoco layers admitted only via an importer (`urdf`, Attach-only) |
| `entry` | no (default `"scene.xml"`) | output entry filename |
| `name` | no | MJCF model name of the output |

`src` (on `Merge` / `Attach` / `Patch`) is ONE string:

- `"ns/name"` or `"ns/name@3"` — pushed env; unversioned floats (resolved
  at compose; the artifact-embedded stack is always pinned `@v`).
- `"./dir"`, `"../dir"`, `"/abs"` — local path, directory in env shape or
  a single sparse-MJCF file (auto-distinguished); dev-only for push.
  Local paths MUST carry the `./`/`../`//` prefix — a bare string is
  always a registry ref.

Element addresses (`Attach.at`, `Update.key`, `Remove.key`) share one
syntax: `kind:name` explicit (`body:fixture/plant`; everything after the
first colon is the name, so attach-keyed names like `right:palm` address
naturally), bare `name` when unambiguous across kinds (ambiguity is an
error asking you to qualify), `option` for the singleton,
`visual:<sub>` for a visual sub-block.

The five ops:

- `{"tag": "Merge", "src": …}` — section-wise union; a name collision
  between merged layers is an **error** (changing things is
  Update/Patch's job). Exception: `option`/`visual`/`compiler` settings
  merge field-wise, later layer wins per field.
- `{"tag": "Attach", "src", "key", "joint", "at"?, "pos"?, "quat"?}`:

  | field | required | meaning |
  | --- | --- | --- |
  | `key` | yes | the identity root, no colon (`"right"` → `right:palm`); prepended to every name and name-reference; duplicate keys are an error |
  | `at` | no, default `"world"` | `"world"`, `"body:<name>"`, or `"site:<name>"` (site pose wins; target may come from any lower layer) |
  | `pos` | no, default `[0,0,0]` | mount position |
  | `quat` | no, default `[1,0,0,0]` | mount orientation (MuJoCo `[w,x,y,z]`) |
  | `joint` | yes | `"rigid"` / `"free"` / `"free-anchored"` |

  One `Attach` per placement — no instances array.
- `{"tag": "Update", "key", ...attrs}` — every prop besides `tag`/`key`
  is an MJCF attribute opinion; JSON values serialize to MuJoCo XML
  conventions (`[0.3, 0.1]` → `"0.3 0.1"`, `true` → `"true"`, enums as
  strings). Matching is **strict** (unknown address = compose error with
  layer index, not a no-op). `name`/`class`/`childclass` cannot be set.
- `{"tag": "Remove", "key"}` — removes the element and its subtree from
  the stack below; reversible by dropping the line. Removable kinds:
  body, geom, joint, site, camera, light, material, mesh, texture,
  actuator, sensor, tendon, equality, key (keyframe).
- `{"tag": "Patch", "src"}` — Update semantics from sparse MJCF (a file
  in the stack's dir, or a pushed opinion env); for opinion sets big
  enough to be their own artifact.

Other frozen semantics: stacks containing any `Attach` strip `<keyframe>`
entries (attach changes dof count); nested composed envs enter as one
layer via their materialized artifact (never unpacked; cycles rejected);
the pinned stack copy records
`"builder": {"engine": "dreamlake-py/<v>", "mujoco": "<v>"}`; local srcs
embed with `"unpinned": true`.

## Workflow

```bash
pip install "dreamlake[compose]"   # once, on the composing machine (python + mujoco)

dreamlake env compose              # materialize ./dreamlake.layers.json (or: compose <path>)
dreamlake env push <out-dir>       # artifact + pinned stack as one version
```

The CLI delegates materialization to the dreamlake-py engine; push / pull /
list need no Python. Registry srcs resolve through the immutable cache
`~/.dreamlake/cache/envs/<ns>/<name>/<version>/`.

**Push discipline** — pushing a directory whose stack contains local
(unpinned) srcs is refused:

- `--push-layers` — push those layers as their own envs first, then the
  composed env. Prefer this: provenance stays resolvable.
- `--allow-local` — push anyway; provenance permanently marked
  non-resolvable. Use only when the user explicitly accepts that.

## The six stack shapes

1. **Scene + embodiment** (swap = edit one line, recompose, push):

```json
{ "schema": "dreamlake.env-layers/v3", "name": "kitchen-sharpa",
  "layers": [
    { "tag": "Merge",  "src": "you/kitchen@3" },
    { "tag": "Attach", "src": "you/sharpa-right@1", "key": "right",
      "at": "world", "pos": [0.45, -0.12, 0.30], "quat": [1, 0, 0, 0],
      "joint": "free-anchored" } ] }
```

2. **Inline opinions** (each line one change; drop a line, it reverts):

```json
{ "schema": "dreamlake.env-layers/v3",
  "layers": [
    { "tag": "Merge",  "src": "you/kitchen@3" },
    { "tag": "Update", "key": "obj/mug", "pos": [0.30, 0.10, 0.02] },
    { "tag": "Update", "key": "light:key", "diffuse": [0.3, 0.3, 0.4] },
    { "tag": "Update", "key": "option", "impratio": 10 },
    { "tag": "Remove", "key": "body:fixture/plant" } ] }
```

3. **Patch file** (same opinions as 2, as sparse MJCF — for big sets):

```json
{ "schema": "dreamlake.env-layers/v3",
  "layers": [
    { "tag": "Merge", "src": "you/kitchen@3" },
    { "tag": "Patch", "src": "./patches/night.xml" },
    { "tag": "Remove", "key": "body:fixture/plant" } ] }
```

```xml
<!-- patches/night.xml — sparse MJCF: only the stated attributes change -->
<mujoco model="night">
  <worldbody>
    <body name="obj/mug" pos="0.30 0.10 0.02"/>
    <light name="key" diffuse="0.3 0.3 0.4"/>
  </worldbody>
  <option impratio="10"/>
</mujoco>
```

4. **Repeated Attach** (an Update above can target `mug2:*` alone):

```json
{ "schema": "dreamlake.env-layers/v3",
  "layers": [
    { "tag": "Merge",  "src": "you/kitchen@3" },
    { "tag": "Attach", "src": "you/mug@2", "key": "mug1",
      "at": "world", "pos": [0.30, 0.10, 0.05], "joint": "free" },
    { "tag": "Attach", "src": "you/mug@2", "key": "mug2",
      "at": "world", "pos": [0.42, -0.08, 0.05], "joint": "free" },
    { "tag": "Update", "key": "mug2:handle", "rgba": [1, 0, 0, 1] } ] }
```

5. **URDF robot layer** (Attach-only; see caveats):

```json
{ "schema": "dreamlake.env-layers/v3", "name": "berry-g1",
  "layers": [
    { "tag": "Merge",  "src": "you/scene-berry@1" },
    { "tag": "Attach", "src": "you/g1@1", "key": "g1",
      "at": "world", "pos": [0, 0, 0.8], "joint": "free" } ] }
```

6. **Nested stack + local dev** (a pushed composed env is one layer; a
   local dir composes freely, push is gated):

```json
{ "schema": "dreamlake.env-layers/v3",
  "layers": [
    { "tag": "Merge",  "src": "you/kitchen-sharpa@2" },
    { "tag": "Attach", "src": "you/wrist-cam-rig@1", "key": "cam",
      "at": "site:right:palm-mount", "joint": "rigid" },
    { "tag": "Merge",  "src": "./staging-decor" },
    { "tag": "Patch",  "src": "you/kitchen-nightshift@1" } ] }
```

## Migrating a v2 stack

v2 files (`{source, compose}` objects) are refused with an error carrying
this mapping — apply it mechanically:

| v2 | v3 |
| --- | --- |
| `{"source": …, "compose": {"mode": "merge"}}` | `{"tag": "Merge", "src": …}` |
| `attach` + `"prefix": "right:"` | `{"tag": "Attach", "key": "right", …}` — no trailing colon, props flat |
| `"instances": […]` | one `Attach` per instance |
| `override` with env/file source | `{"tag": "Patch", "src": …}` (or inline `Update`s for small sets) |
| `compose.delete: [{"elem", "name"}]` | `{"tag": "Remove", "key": "kind:name"}` |
| `{"env"}/{"path"}/{"file"}` sources | one `src` string; local paths start with `./` |

## Errors and remedies

| error | when | remedy |
| --- | --- | --- |
| merge name collision | two Merge layers define a same-named element | rename in one layer; if the upper layer is meant to *change* it, use `Update`/`Patch` |
| strict-match miss | an `Update`/`Remove`/`Patch` opinion names an element the stack below doesn't have (error reports the layer index) | fix the typo; after an `Attach`, target the **keyed** name (`right:palm`, `mug2:handle`) |
| ambiguous address | a bare `key` matches several kinds (a body and a geom named alike) | qualify: `body:thing` |
| env src not resolved ("resolve refs first") | the Python engine was invoked directly on a stack still containing registry srcs | run through `dreamlake env compose` (it resolves refs into the cache first); for private layers check the active login/remote |
| missing Python engine | dreamlake-py or its mujoco extra is absent on the composing machine | `pip install "dreamlake[compose]"`; machines that only push/pull/list don't need it |

## Caveats (verified, not hypothetical)

- **URDF layers are Attach-only** (URDF cannot express a world) and import
  **unactuated**: URDF `<transmission>` has no MuJoCo mapping, so the robot
  arrives with `nu = 0` and goes limp under gravity in a physics stack. The
  compose report carries an "unactuated import" warning. Remedy inside the
  stack model: add `Update` ops (or a `Patch` layer) contributing
  damping/actuators, or present the layer as visualization-grade in the env
  description. The composer also reconciles a root freejoint the URDF may
  already declare — it never double-adds one.
- **Key targeting**: `Attach` manufactures new identities under its `key`;
  every `Update`/`Remove`/`Patch` above must use the keyed names.
- **Strict matching is a feature**: an opinion naming a missing element
  fails compose deliberately — never "fix" it by removing the opinion
  without checking whether the stack order or a key is what's wrong.
- **Order is the priority.** Base content first, attaches next, opinions
  last is the conventional reading order; whatever you write, later wins.
- **Pin when it matters**: floating refs (`you/kitchen`) re-resolve on every
  compose; pin `@v` for reproducibility. The artifact's embedded stack is
  always pinned regardless.
