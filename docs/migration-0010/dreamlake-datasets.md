# Migration: dreamlake-datasets

Merged from `dreamlake-source`, `dreamlake-dataset-viz`, `remote-source-check`
(all three serve "get data reachable and rendered"). **Decision:** `sim-to-mcap`
was listed under this skill in RFC 0010 §4 but is kept as its own skill — rolling
a trained policy out in a simulator is a distinct goal someone installs on its
own (merge-caution rule 2a); it `requires` `dreamlake-datasets` and hands off by
name. See `_migration/sim-to-mcap.md`.

One source file per action (merge-caution rule 3): `prepare-data.md` was split
into two actions along its own §1/§2 boundary; nothing was concatenated.
